How a workflow could be enforced

You cannot prove an agent used a skill. You can require the artifact that step leaves behind. So define each step by its artifact.

Enforcement ladder

Strongest at the top
6Agents in projects/agents/: independent judge
5Claude Code hooks: hard, in-session
4Mechanical gate: hard
3Workflow record: checkable
2Router skill: soft
1Written convention: advisory
Weakest at the bottom

1. Written conventiona scenario-to-skills table in CLAUDE.mdyesread onlyadvisory

3. Workflow recordeach PR carries a small record: scenario, each step done or skipped with a reason, a link to its evidenceyesyescheckable
4. Mechanical gatea script in CI reads the record and fails when a required step has no evidence; factory Review treats a missing step as a blocker; uses the existing rework roundsyesyeshard
5. Claude Code hookscommitted project settings: a Stop hook that refuses to finish until the check ran, a PreToolUse hook that blocks git push until the record existsyesyes (the factory loads project settings)hard, in-session
6. Agents in projects/agents/small Agent SDK programs with a fixed tool list and a strict output schema, run beside the workby hand todaynot wired yetindependent judge

Three constraints found in the repo

(a) Almost every skill in both suites is user-only (disable-model-invocation), so an agent cannot invoke them; only a person typing the command can.

(b) The factory runner installs plain Claude Code with project settings only: no plugins, no home-folder skills, and the repo has no root .claude/ folder yet.

(c) Agents in projects/agents/ load no skills (settingSources: []), run on Haiku 5.5, cap at $1 a run and are launched by hand.

Agent ideas (not built)

ticket-sizer

Reads an issue, proposes a scenario (small, medium, big, huge, POC, bug) through a strict schema. Code checks the answer against the allowed list. Feeds rung 2 and 3.

workflow-auditor

Read-only. Reads a PR and its workflow record, answers pass or fail per required step with the evidence it found. Feeds rung 4. Never the agent that wrote the change.

verify-runner

Runs a Project's ./check --json, returns the Summary unchanged. The three sandboxes already give it a shared format.

With a workflow record on every PR, the Lab can run the same Bench case under Matt's tree, Lauren's tree and a hybrid, and compare passed out of N. That is how we test them ourselves.
