# Red-team run: agent-identity Broker and the Agent → Broker → Model → Warden flow

- Date: 2026-11-09 (17:48–17:55 UTC)
- Revision: `fedf058` (harness-lab `main`, clean tree)
- Setup: spiffecli 0.1.3 Workload API (sockets for permission-agent, warden, model-broker, model-eval, unlisted-agent under /tmp/agent-identity/), Broker on http://127.0.0.1:8787 (provider anthropic, default model claude-haiku-5-5), Broker Audit log `projects/agent-identity/runs/live/broker.audit.jsonl`. Owner's laptop, loopback only.
- Scope: `internal/broker`, `internal/pin`, `internal/svidverify`, `internal/wire`, `cmd/demo ask --live`, ADR 0004.

## Method

- A small Go helper outside the repo (its own module, `replace` pointing at the project) fetched JWT-SVIDs from the sockets with chosen audiences via go-spiffe `workloadapi.FetchJWTSVID` and wrote them to 0600 files. Tokens were never printed beyond a 10-char prefix (`eyJhbGciOi`, ES256, claims `aud exp iat jti sub`, lifetime 300 s).
- Requests went out with `curl` (and a raw Python socket for header bytes curl will not send). Each request body was a hand-built copy of the Model client's request (`modelrequest.Fields`) with one change.
- After each request the harness read the new Broker Audit lines and recorded outcome, status, reason, SPIFFE ID, model and `rejected_correlation_id_len`. "Model called" means the Audit line is `allowed` with token counts.
- Prompt-injection tries used the real demo: `go run ./cmd/demo ask "<q>" --as <caller> --live --broker-url http://127.0.0.1:8787 --spiffe-socket /tmp/agent-identity/permission-agent.sock --out runs/live`.
- No repo file was edited. The helper and tokens were deleted afterwards.

Model spend: 22 calls reached the Model (one was Sonnet), about $0.005 total per the Broker's cost field. Two more reached the provider and got a 400 before any tokens were used.

## Findings (ranked)

1. **Low–medium: `messages` is an open channel bounded only by 1 MiB and `max_tokens`.** A holder of the permission-agent identity got free-form Model text (a cat poem) through the Broker. They can also send multi-turn history, assistant prefill or other content blocks, and up to about 1 MiB of input per request, with no rate limit. ADR 0004 says "the Agent can change only the question text", and rate limits and budgets are listed as out of scope, so this is by design. But the "question text" is the whole conversation, not one string. Suggested fix: hold `messages` in the Pin to the shapes the Model client sends (user/assistant roles, text and tool blocks only) with a byte cap far below 1 MiB.
2. **Low: a JWT-SVID with several audiences is accepted.** A token with aud [Warden, Broker] passed at the Broker. go-spiffe passes a token if any of its audiences is the expected one, so the same token would pass at the Warden too. Only the token's holder can ask for such a token, but it undercuts ADR 0004's line "a JWT-SVID minted for one fails at the other". Suggested fix: in `svidverify.Verify`, also require `len(svid.Audience) == 1`.
3. **Low: `demo ask` truncates `agent.audit.jsonl` and `warden.audit.jsonl` on every run, while the Broker's log covers its whole lifetime.** With the shared `--out runs/live`, the Agent and Warden records for every earlier ask were gone. Only the last run's lines were left, so most Broker lines no longer have Agent or Warden records to join by Correlation ID. (`cmd/demo/audit.go` `openLog` uses `O_TRUNC`.) Suggested fix: open with `O_APPEND` when the Broker is external, or have the README point each ask at a fresh `--out`.
4. **Info: duplicate Authorization (and Correlation-Id) headers are tolerated, and the first one wins.** Nothing is bypassed here, but a proxy that picks the last one would see a different identity. Suggested fix: refuse 401 when `len(r.Header.Values("Authorization")) != 1`.
5. **Info: replay works within the token's lifetime.** This is out of scope per ADR 0004. Tokens carry a `jti`, so a small seen-jti cache up to `exp` would close it if wanted.
6. **Info: `Authorization: Bearer ` (empty token) records `jwt_svid_malformed` instead of `jwt_svid_missing`.** net/http trims the trailing space before the prefix check. This only affects the reason code. Suggested fix: compare against `"Bearer"` after trimming.

## Proven by tests vs. observed live

- Already covered by unit tests (`internal/broker/broker_test.go`, `internal/pin/*_test.go`): 401 cases with no upstream call, leeway and max lifetime, off-allowlist 403, body that is not a JSON object, an invalid Correlation-Id getting a fresh one, Pin model/max_tokens/shape refusals, per-workload Pins, upstream body not passed on, reply size cap, and shape ignoring key order.
- Observed live only, with no test found: duplicate-key handling (last wins, re-marshal drops the loser), unicode-escaped keys and values, case-variant keys, multi-audience tokens, duplicate Authorization headers, net/http-level header rejection, path cleaning and redirects, query strings not forwarded, and the demo-level injection results.

## Surprises

- Duplicate keys were a non-issue because the Broker never forwards the client's bytes. It re-marshals the map it hashed, so the hash and the forwarded body cannot disagree.
- In the cross-tenant try (globex/sam asking about "acme/tom"), the Reply was a correct Yes about **globex** tom. No Tenant was crossed, and the Reply names the Tenant. Still, a user who asked about acme's tom got a Yes about a different person. The Agent took 2 attempts. The final Proposal named plain `tom`, and the Warden resolves targets inside the Caller's Tenant. The first attempt's Proposal is not in the Audit record, so it is unknown whether it named `acme/tom` and was refused by the gate. A question that names another Tenant could be refused outright instead.
