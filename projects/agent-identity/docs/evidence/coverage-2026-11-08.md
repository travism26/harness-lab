# Coverage and behaviour-to-test map, 2026-11-08

Part (b) of the hardening spec (#78), ticket #80. This is a hobby lab: the goal is to see which promised behaviours have a test behind them, not to hit a number. There is no coverage threshold and no new tooling.

## Commands

Run from `projects/agent-identity/`:

```sh
git rev-parse HEAD
go version
./check
go test -count=1 -coverprofile=<outside the repo>/cover.out ./...
go tool cover -func=<outside the repo>/cover.out
```

The profile was written to a directory outside the repo, never into the repo. Coverage is per package (no `-coverpkg`), so a package counts only the statements its own tests reach.

- Baseline revision: `d995766` (merge of PR #82), `go version go1.27.3 darwin/arm64`.
- After-ticket numbers were re-measured at `c2b8738`, the last commit that changes tests; later commits only touch this document. No production code changed. Same Go version, same commands. The review-fix commit left every package's coverage unchanged.

Statement coverage doesn't show branch completeness: a line can be covered while one arm of its condition never runs (for example the `ok && TrimSpace(token)==""` arm in `verifyJWTSVID`, and the `err != nil && Status == 200` arm in `Ask`, were both on covered lines before this ticket). Race detection (`./check` runs `-race`) isn't coverage either; the profiles came from a separate run without `-race`. The low numbers for standin/model, standin/workload and wire come from the per-package scope: other packages' tests use them heavily, their own tests barely do. They are test doubles and shared types, not security logic.

## Behaviour to test map

Seams: Ask = `Agent.Ask` with a real loopback Warden and the scripted Model stand-in; Warden HTTP = hand-built POST /lookup; CLI = cmd/demo; unit = direct call. NEW marks a test added by this ticket. Packages are under `projects/agent-identity/internal/` unless noted. Test files live in the package folder, for example `projects/agent-identity/internal/agent/failclosed_test.go`.

Two NEW seams are narrower than they look:

- The Warden bad-answer rows (`TestWardenNoAnswerIsUnreachableNeverNo`) use an `httptest` server standing in for the Warden, at the Ask seam. The real loopback Warden is not involved in those rows.
- The Model 401 / 403 live rows use the scripted stand-in Model server, configured with provider `anthropic`. They prove the `live` label and that the Agent does not fall back to a stand-in answer. They do not run the real Anthropic client path or a real Anthropic response.

## Remaining gaps

- Model 200 with an unreadable body (decode error in `projects/agent-identity/internal/modelclient/modelclient.go`): needs a raw-body Model server; the Model-client unit seam was out of scope. Risk: low, same `provider_error` branch family as the other Model failures.
- The Warden's or the other Agent's socket failing to open in the demo, and the real `openWorkloadAPI` dial with its 10 s timeout: demo-CLI only and the real dial needs a live SPIRE. Risk: low; part (c) is meant to cover the missing-socket row live.
- Leeway boundary to the second: go-spiffe takes no injectable clock, so tests check 30 s inside and 90 s outside the 60 s leeway. Risk: the leeway could change anywhere between those without a failure.
- `Bearer   ` over HTTP: net/http trims trailing spaces, so the Warden sees `Bearer` and answers `jwt_svid_malformed`. The `jwt_svid_missing` arm for a whitespace-only token is not reachable through HTTP and stays untested. Risk: low.
- The Model prompt not naming the Caller: `TestPromptHoldsOnlyTheQuestion` only checks the word "caller" is absent. Risk: low, since the Model client has no Caller input by construction.
- Prompt override: a scripted stand-in can't show it. It rests on the structural rows (gate, Tenant from the assertion, Warden decides) and part (c)'s live row. Risk: a real Model might follow an injected instruction; only the live row can show how it behaves, and the structure limits the harm to a Proposal the Warden still checks.
- Provider key and private keys are plain `string` / `*ecdsa.PrivateKey`, not typed, so trustlint doesn't cover them; only the runtime canaries do. Risk: a log line printing a `ModelConfig` would pass trustlint.
- `TestUnreadableDotEnvIsAnErrorThatHoldsNoValue` asserts only `err != nil`; its name overstates it. Not counted as evidence for "no secret in errors".
- Audit-write fail-open: if the Warden can't encode or write its Audit record it logs an error and still serves the response (`projects/agent-identity/internal/warden/audit.go`); the Agent's Audit write discards its error with no log at all (`projects/agent-identity/internal/agent/audit.go`). This is current behaviour, documented here, not fixed and not tested. Risk: audit records can be lost silently while answers are still served.
- The Model client's 20 s call ceiling (`callTimeout`) is a const and untested. The new timeout test proves the caller-deadline path, not the 20 s value. Risk: low.
