## What changed before this baseline

The first sweep the same day failed the bar, and it surfaced two fixes that are in the same change as this file.

1. **The Model didn't know the permission vocabulary.** Haiku 5.5 scored paraphrase 9/18 and named 16/18. It proposed `invoice:view` for "view invoices" or "see invoices", `permission:lookup` for "look up permissions", and `permissions:read` with a plural resource. Sonnet and Opus missed the same cases (paraphrase 9/18 and 12/18). The system prompt now says resources are singular, and that `read` covers view, see and look up while `approve` covers sign off. Any other permission is still written as asked, so the out-of-catalog cases (`user:delete`, `report:export`, `payment:refund`) still reach the Warden and get its 422.
2. **A repair retry broke when the Model had thought first.** The retry echoed the Model's turn without the thinking block's `thinking` and `signature` fields, and the API answered `messages.1.content.0.thinking.thinking: Field required`, which scored as `provider_error`. Content blocks are now echoed exactly as received, pinned by `TestRepairRetryEchoesThinkingBlockUnchanged`.

An earlier change (PR #74) told the Model that target names are lowercase. Before it, Haiku 5.5 sent `Tom` on every first try and needed a repair retry.

A re-run adds a new dated file and keeps this one.
